注意：Guardrails（护栏）是一个实验性功能。其 API 和行为在未来的版本中可能会发生变化。

护栏（Guardrails）是一种机制，可以让你验证大语言模型（LLM）的输入和输出，以确保它们符合你的预期。你可以使用护栏完成以下一些事情：

- 验证用户输入是否超出范围
- 确保输入在调用大语言模型之前满足某些条件（即防范提示词注入攻击）
- 确保输出格式正确（例如，是一个具有正确模式的 JSON 文档）
- 确保大语言模型的输出符合业务规则和约束（例如，如果是公司 X 的聊天机器人，则响应中不应包含任何对竞争对手 Y 的引用）。
- 检测幻觉
以上只是一些示例。你还可以使用护栏完成许多其他事情。

注意：护栏仅在使用 AI Services 时可用。它们是一个更高层次的构造，无法应用于 ChatModel 或 StreamingChatModel。

## 实现护栏

理想情况下，护栏实现应该遵循单一职责原则，这意味着每个护栏类应该只验证一件事。然后，将多个护栏链接在一起，以防范多种情况。

护栏在链中的顺序很重要。链中第一个失败的护栏将触发整体的失败。确保能够捕获最多失败的护栏位于链的早期，而那些失败概率较低的更具体的护栏则放在链的末尾。

可以重写其验证文本的护栏可以声明在链中的任何位置。它们不需要为了其重写内容能够到达调用者而被声明为最后一个。详细信息请参阅《链中可重写的护栏》。

还请记住，护栏自身也可以调用其他服务，甚至调用其他大语言模型交互。如果这些类型的护栏具有执行开销或金钱成本，请务必将其纳入考量。你可能希望将成本更高的护栏放在链的末尾。

注意："昂贵"一词可以指执行需要一些时间，或者与之相关的金钱价值。

### 链中可重写的护栏

护栏的功能不仅仅是接受或拒绝它所接收到的文本。通过返回带有重写的成功（successWith(...)），它会替换链中后续护栏以及最终调用者所看到的文本。这就是编辑、屏蔽和格式修复类护栏的工作方式。

重写按照以下规则在链中进行组合。这些规则同时适用于输入和输出护栏，无论操作是同步的还是异步/流式的：

- 位于可重写护栏之后的每个护栏验证的是重写后的文本，而不是原始文本。
- 重写会在后续的普通 success() 之后保留。success() 表示"我接收到的文本是可接受的"，后续护栏接收到的文本已经是重写后的文本，因此批准它不会恢复到原始文本。
- 后发生的重写会覆盖先发生的重写。重写按链顺序组合，因此最后一个重写文本的护栏胜出。
- 因此，可重写的护栏无需是链中的最后一个护栏，其重写结果就能返回给调用者。

注意：一旦输出护栏链中的任何护栏重写了输出，后面的 fatal with retry 或 fatal with reprompt 结果就不被允许，因为大语言模型将被要求为已经被重写的文本产生新的响应。在这种情况下，执行将以 OutputGuardrailException 中止，其消息包含 "Retry or reprompt is not allowed after a rewritten output"。

## 输入护栏（Input Guardrails）

输入护栏是在调用大语言模型之前调用的函数。输入护栏的失败会阻止大语言模型被调用。输入护栏是调用大语言模型之前的最后一步。它们在任何 RAG（检索增强生成）操作完成之后被调用。

### 实现输入护栏

输入护栏通过实现 InputGuardrail 接口来实现。InputGuardrail 接口有两个 validate 方法变体，至少需要实现其中一个：

```
InputGuardrailResult validate(UserMessage userMessage);InputGuardrailResult validate(InputGuardrailRequest params);
```

第一个变体用于简单的护栏，或者当护栏只需要访问 UserMessage 时使用。

第二个变体用于需要更多信息的更复杂的护栏，例如聊天记忆/历史、用户消息模板、增强结果或传递给模板的变量。有关更多信息，请参阅 InputGuardrailRequest。

以下是你可以做的一些事情的示例：

- 检查增强结果中的文档数量是否足够
- 确保用户没有重复提问同一个问题
- 缓解潜在的提示词注入攻击
- 使用社区的 Prompt Repetition 模块重写符合条件的单文本输入

无论操作是同步的还是异步/流式的，都可以使用输入护栏。

### 输入护栏的结果

输入护栏可以具有以下结果。InputGuardrail 接口上有一些辅助方法可以提供这些结果：

| 结果（Outcome） | InputGuardrail 上的辅助方法 | 描述（Description） |
| success | success() | - 输入有效。 - 链中的下一个护栏被执行。 - 如果最后一个护栏通过，则会调用大语言模型。 - 如果链中较早的护栏重写了用户消息，success 表示重写后的用户消息是有效的。重写会被保留。详见《链中可重写的护栏》。 |
| 成功并带有替代结果（success with alternate result） | successWith(String) | - 与 success 类似，但在进入下一步（链中的下一个护栏或调用大语言模型）之前会修改用户消息。 - 由护栏进行的重写会覆盖链中较早护栏所做的任何重写。 |
| 失败（failure） | failure(String) 或 failure(String, Throwable) | - 输入无效，但链中的下一个护栏会继续执行，以累积所有可能的验证问题。 - 大语言模型不会被调用。 - 如果传入了 Throwable，消费者可以捕获 InputGuardrailException 并检查其原因。它将是在此处传入的 Throwable。 |
| 致命错误（fatal） | fatal(String) 或 fatal(String, Throwable) | - 输入无效，执行以 InputGuardrailException 中止。 - 大语言模型不会被调用。 - 如果传入了 Throwable，消费者可以捕获 InputGuardrailException 并检查其原因。它将是在此处传入的 Throwable。 |

### 声明输入护栏

有多种声明输入护栏的方式，按优先级顺序列出如下：

- 直接在 AiServices builder 上设置的 InputGuardrail 实现类名或实例。
- 放置在单个 AI Service 方法上的 @InputGuardrails 注解。
- 放置在 AI Service 类上的 @InputGuardrails 注解。
无论它们是如何声明的，输入护栏始终按照它们在列表中出现的顺序执行。被列表中任何护栏重写的用户消息对其后续的护栏可见，除非后续的护栏再次重写它，否则它也会对大语言模型可见。

#### AiServices builder

直接在 AiServices builder 上设置的 InputGuardrail 实现类名或实例具有最高优先级，这意味着如果通过其他任何方式声明了输入护栏，那么直接设置在 builder 上的将被使用。

```
public interface Assistant { String chat(String question); String doSomethingElse(String question);}var assistant = AiServices.builder(Assistant.class) .chatModel(chatModel) .inputGuardrailClasses(FirstInputGuardrail.class, SecondInputGuardrail.class) .build();
```

或者

```
public interface Assistant { String chat(String question); String doSomethingElse(String question);}var assistant = AiServices.builder(Assistant.class) .chatModel(chatModel) .inputGuardrails(new FirstInputGuardrail(), new SecondInputGuardrail()) .build();
```

信息：如果你想要一个现成的、实验性的输入护栏，它使用提示词重复（prompt repetition）重写符合条件的单文本输入，请参阅社区的 Prompt Repetition 模块。

在第一种场景中，传递的是实现 InputGuardrail 的类。这些类的新实例是通过反射动态创建的。

信息：类到实例的转换方式可以被自定义。例如，使用依赖注入的框架（如 Quarkus 或 Spring）可以使用扩展点来基于它们管理类实例的方式来提供实例，而不是每次都通过反射创建新实例。

#### 单个 AI Service 方法上的注解

放置在单个 AI Service 方法上的 @InputGuardrails 注解具有次高优先级。

```
public interface Assistant { @InputGuardrails({ FirstInputGuardrail.class, SecondInputGuardrail.class }) String chat(String question); String doSomethingElse(String question);}var assistant = AiServices.create(Assistant.class, chatModel);
```

在此示例中，只有 chat 方法具有护栏。

- 在 chat 方法上，首先调用 FirstInputGuardrail。
- 只有当它成功时，才会调用大语言模型。
- 仅当 FirstInputGuardrail 未产生致命结果时，才会调用 SecondInputGuardrail。
- FirstInputGuardrail 或 SecondInputGuardrail 都可以重写用户消息。
- 如果 FirstInputGuardrail 重写了用户消息，则 SecondInputGuardrail 将接收新的用户消息作为输入。

doSomethingElse 方法没有任何护栏。

#### AI Service 类上的注解

放置在 AI Service 类上的 @InputGuardrails 注解具有最低优先级。

```
@InputGuardrails({ FirstInputGuardrail.class, SecondInputGuardrail.class })public interface Assistant { String chat(String question); String doSomethingElse(String question);}var assistant = AiServices.create(Assistant.class, chatModel);
```

在此示例中，chat 和 doSomethingElse 方法都具有护栏。

- 与上一个示例相同，首先调用 FirstInputGuardrail。
- 只有当它成功时，才会调用大语言模型。
- 仅当 FirstInputGuardrail 未产生致命结果时，才会调用 SecondInputGuardrail。
- FirstInputGuardrail 或 SecondInputGuardrail 都可以重写用户消息。
- 如果 FirstInputGuardrail 重写了用户消息，则 SecondInputGuardrail 将接收新的用户消息作为输入。

## 输出护栏（Output Guardrails）

输出护栏是在大语言模型产生其输出之后执行的函数。输出护栏的失败允许更高级的场景，例如重试或重新提示，以帮助改进响应。它们在所有其他操作（包括函数/工具调用）完成后被调用。

### 实现输出护栏

与输入护栏类似，输出护栏通过实现 OutputGuardrail 接口来实现。OutputGuardrail 接口有两个 validate 方法变体，至少需要实现其中一个：

```
OutputGuardrailResult validate(AiMessage responseFromLLM);OutputGuardrailResult validate(OutputGuardrailRequest params);
```

第一个变体用于简单的护栏，或者当护栏只需要访问生成的 AiMessage 时使用。

第二个变体用于需要更多信息的更复杂的护栏，例如整个聊天响应、聊天记忆/历史、用户消息模板或传递给模板的变量。有关更多信息，请参阅 OutputGuardrailRequest。

以下是你可以做的一些事情的示例：

- 确保输出格式正确（例如，是一个具有正确模式的 JSON 文档）
- 检测大语言模型的幻觉
- 验证大语言模型的响应包含某些信息

### 输出护栏的结果

输出护栏可以具有以下结果。OutputGuardrail 接口上有一些辅助方法可以提供这些结果：

| 结果（Outcome） | OutputGuardrail 上的辅助方法 | 描述（Description） |
| success | success() | - 输出有效。 - 链中的下一个护栏被执行。如果最后一个护栏通过，则输出返回给调用者。 - 如果链中较早的护栏重写了输出，success 表示重写后的输出是有效的。重写以及附加到它的任何结果对象都会被保留。详见《链中可重写的护栏》。 |
| 成功并重写（success with rewrite） | successWith(String) 或 successWith(String, Object) | - 与 success 类似，但输出在其原始形式下无效，并且已经被重写以使其有效。 - 下一个护栏针对重写后的输出执行。如果最后一个护栏通过，则输出返回给调用者。 - 由护栏进行的重写会覆盖链中较早护栏所做的任何重写。 - 使用 successWith(String, Object) 时，结果对象与其所派生的重写文本一起传递。因此，仅重写文本的后续护栏（successWith(String)）会覆盖该结果对象并丢弃它，因为该结果对象不再对应于当前文本。而后续的普通 success() 不会丢弃它。 |
| 失败（failure） | failure(String) 或 failure(String, Throwable) | - 输出无效，但链中的下一个护栏会继续执行，以累积所有可能的验证问题。 - 验证失败作为 OutputGuardrailException 返回给用户。 |
| 致命错误（fatal） | fatal(String) 或 fatal(String, Throwable) | 输出无效，执行以抛给调用者的 OutputGuardrailException 中止。 |
| 致命错误并重试（fatal with retry） | retry(String) 或 retry(String, Throwable) | - 与 fatal 类似，但使用与原始调用相同的提示词和聊天历史再次调用大语言模型。 - 如果在可配置的重试次数后失败仍然存在，则执行以抛给调用者的 OutputGuardrailException 中止。 - 如果护栏在重试后通过，则整个护栏链会从头开始重新执行。 |
| 致命错误并重新提示（fatal with reprompt） | reprompt(String, String) 或 reprompt(String, Throwable, String) | - 与 fatal with retry 类似，但使用护栏提供的新提示词再次调用大语言模型。 - 在这种情况下，护栏提供一个附加消息附加到先前的用户消息，然后使用新的用户消息和原始的聊天历史向大语言模型发送新请求。 - 如果在可配置的重试次数后失败仍然存在，则执行以抛给调用者的 OutputGuardrailException 中止。 - 如果护栏在重新提示后通过，则整个护栏链会从头开始重新执行。 |

重试或重新提示会重新发送原始调用的会话（系统消息、用户消息、任何工具调用和结果，以及被拒绝的响应），无论 AI Service 是否具有聊天记忆。如果没有聊天记忆，则会话仅在调用期间保留。


### 流式响应上的输出护栏

输出护栏也可以用于具有流式响应的操作：

```
public interface StreamingAssistant { @OutputGuardrails({ FirstOutputGuardrail.class, SecondOutputGuardrail.class }) TokenStream streamingChat(String message);}
```

在这种情况下，输出护栏将在整个流完成时被执行，更具体地说，是在 TokenStream.onCompleteResponse 被调用时执行。onPartialResponse 将被缓冲，并在护栏成功后被重放。

在链中的重试或重新提示最终成功的情况下，整个链将被同步重新执行。每个护栏将按照原始顺序依次重新执行。一旦链完成，结果将传递给 TokenStream.onCompleteResponse。

### 开箱即用的输出护栏

在以下几种常见用例中，LangChain4j 提供了输出护栏的实现：

| 护栏类（Guardrail class） | 描述（Description） |
| JsonExtractorOutputGuardrail | 一个输出护栏，用于检查响应是否可以从 JSON 成功反序列化为某种类型的对象。 - 使用 Jackson ObjectMapper 尝试反序列化一个对象。 - 如果响应无法反序列化为预期的对象类型，则会重新提示大语言模型。 - 可以直接使用，也可以被扩展和自定义（有几个 protected 方法可以被重写以自定义行为）。 |
| DecisionModelOutputGuardrail | 一个使用决策模型检查模型响应的输出护栏。 - 每项检查都是一个是/否问题，其中"是"表示响应必须被拒绝，例如"响应是否泄露了个人数据？"。决策模型还会接收最后一条用户消息。 - 被拒绝的响应会以致命结果失败，或者，如果已配置，则会重新提示模型。 |

langchain4j-test 模块中提供了一些基于 AssertJ 的单元测试实用工具。

- Gradle (Kotlin)

```

```

```

```

一旦你添加了该依赖，就可以执行以下这些类型的验证：

```
import static dev.langchain4j.test.guardrail.GuardrailAssertions.assertThat;import dev.langchain4j.data.message.AiMessage;import dev.langchain4j.guardrail.GuardrailResult.Result;class Tests { MyOutputGuardrail outputGuardrail = new MyOutputGuardrail(); @Test void test() { var aiMessage = AiMessage.from("Some output"); var result = outputGuardrail.validate(aiMessage); // 以下只是你可以做的一些示例 assertThat(result) .isSuccessful() .hasResult(Result.FATAL) .hasFailures() .hasSingleFailureWithMessage("Hallucination detected!") .hasSingleFailureWithMessageAndReprompt("Hallucination detected!", "Please LLM don't hallucinate!") .assertSingleFailureSatisfied(failure -> assertThat(failure)...) .withFailures()..... }}
```

信息：有关更多详细信息，请参阅 GuardrailAssertions 和 OutputGuardrailResultAssert 类。

注意：执行 I/O 的护栏可以实现 validateAsync(...) ，这样当
AI Service 以非阻塞模式使用时，它不会阻塞线程。输入和输出护栏（包括工具感知的重新提示）支持
异步和响应式模式。
请参阅《非阻塞与响应式》。

## 混合与匹配

你可以随意混合和匹配输入和输出护栏！

```
public class MyObjectJsonOutputGuardrail extends JsonExtractorOutputGuardrail<MyObject> { public MyObjectJsonOutputGuardrail() { super(MyObject.class); }}@InputGuardrails({ FirstInputGuardrail.class, SecondInputGuardrail.class })@OutputGuardrails(value = SomeOutputGuardrail.class, maxRetries = 5)public interface Assistant { String chat(String message); @InputGuardrails(PatternBasedPromptInjectionGuardrail.class) @OutputGuardrails(MyObjectJsonOutputGuardrail.class) MyObject chatAndReturnJson(String message);}var outputGuardrailsConfig = OutputGuardrailsConfig.builder() .maxRetries(10) .build();var assistant = AiServices.builder(Assistant.class) .chatModel(chatModel) .inputGuardrails(new AnotherInputGuardrail()) .outputGuardrailsConfig(outputGuardrailsConfig) .build();
```

在此示例中，由于 AnotherInputGuardrail 是设置在 AiServices builder 上的，所以 Assistant 上的所有方法都具有这一个输入护栏。此外，由于配置也是设置在 AiServices builder 上的，所以所有输出护栏都具有 maxRetries 值 == 10。

chat 方法具有一个输出护栏 SomeOutputGuardrail，其 maxRetries 值 == 10。

chatAndReturnJson 方法具有一个输出护栏 MyObjectJsonOutputGuardrail，其 maxRetries 值 == 10。

## 扩展点

护栏系统是以可组合的方式构建的，因此它可以在其他下游框架（如 Quarkus 或 Spring Boot）中被扩展和重用。本节描述了提供的一些扩展点或"钩子"。

所有这些扩展点都使用 Java 服务提供者接口（Java SPI）。

| 扩展点接口（Extension point interface） | 用途（Purpose） |
| ClassInstanceFactory | 提供类的实例。 - 旨在将实例的创建/检索委托给其他方式。 - 如果未提供，则使用反射通过默认构造函数创建一个实例。 - 其他框架（如 Quarkus 或 Spring）可能会使用它们自己的 bean 容器来提供类的实例。这些框架将提供一个实现。 - 一个 Quarkus 实现可能看起来像 CDIClassInstanceFactory - 一个 Spring 实现可能看起来像 ApplicationContextClassInstanceFactory |
| ClassMetadataProviderFactory | 提供对类元数据的访问。 - 用于扫描 AiService 接口上的方法，并查找和处理 @InputGuardrails/@OutputGuardrails 注解。 - 如果未找到其他实现，ReflectionBasedClassMetadataProviderFactory 是默认实现，它使用反射提供类元数据。 |
| GuardrailServiceBuilderFactory | 为构建 GuardrailService 实例提供 builder 实例。如果应用程序或框架需要自定义构建 GuardrailService 实例的方式，则会实现此接口。 |
| InputGuardrailsConfigBuilderFactory | - 用于覆盖和/或扩展默认 InputGuardrailsConfigBuilder 的 SPI。 - 其他框架可能会提供它们自己的实现，其中包含输入护栏的额外附加配置。 - 还将允许其他框架通过其他机制（例如属性文件）驱动输入护栏的配置。 |
| OutputGuardrailsConfigBuilderFactory | - 用于覆盖和/或扩展默认 OutputGuardrailsConfigBuilder 的 SPI。 - 其他框架可能会提供它们自己的实现，其中包含输出护栏的额外附加配置。 - 还将允许其他框架通过其他机制（例如属性文件）驱动输出护栏的配置。 |
| InputGuardrailExecutorBuilderFactory | - 用于覆盖和/或扩展默认 InputGuardrailExecutorBuilder 的 SPI，后者负责构建 [`InputGuardrailExecutor`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/guardrail/InputGuardrailExecutor.java) 实例。 |
| OutputGuardrailExecutorBuilderFactory | - 用于覆盖和/或扩展默认 OutputGuardrailExecutorBuilder 的 SPI，后者负责构建 [`OutputGuardrailExecutor`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/guardrail/OutputGuardrailExecutor.java) 实例。 |
