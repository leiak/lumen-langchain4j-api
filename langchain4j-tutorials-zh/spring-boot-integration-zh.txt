LangChain4j 为以下场景提供了 Spring Boot 启动器：

- 常用的集成
- 声明式 AI Services

## Spring Boot 启动器

Spring Boot 启动器可通过配置文件帮助你创建和配置
大语言模型，
嵌入模型，
向量存储，
以及其他核心 LangChain4j 组件。

要使用某个 Spring Boot 启动器，
请导入相应的依赖。

Spring Boot 启动器依赖的命名规范为：

- langchain4j-{integration-name}-spring-boot4-starter 用于 Spring Boot 4
- langchain4j-{integration-name}-spring-boot-starter 用于 Spring Boot 3

例如，对于 OpenAI（langchain4j-open-ai）：

Spring Boot 4：

```
<dependency> <groupId>dev.langchain4j</groupId> <artifactId>langchain4j-open-ai-spring-boot4-starter</artifactId> <version>1.22.0-beta32</version></dependency>
```

Spring Boot 3：

```
<dependency> <groupId>dev.langchain4j</groupId> <artifactId>langchain4j-open-ai-spring-boot-starter</artifactId> <version>1.22.0-beta32</version></dependency>
```

然后，你可以在 application.properties 文件中按如下方式配置模型参数：

```
langchain4j.open-ai.chat-model.api-key=${OPENAI_API_KEY}langchain4j.open-ai.chat-model.model-name=gpt-4olangchain4j.open-ai.chat-model.log-requests=truelangchain4j.open-ai.chat-model.log-responses=true...
```

在这种情况下，会自动创建一个 OpenAiChatModel 实例（ChatModel 接口的一个实现），
你可以在需要的地方自动注入它：

```
@RestControllerpublic class ChatController { ChatModel chatModel; public ChatController(ChatModel chatModel) { this.chatModel = chatModel; } @GetMapping("/chat") public String model(@RequestParam(value = "message", defaultValue = "Hello") String message) { return chatModel.chat(message); }}
```

如果你需要一个 StreamingChatModel 实例，
请使用 streaming-chat-model 属性而非 chat-model 属性：

```
langchain4j.open-ai.streaming-chat-model.api-key=${OPENAI_API_KEY}...
```

## 用于声明式 AI Services 的 Spring Boot 启动器

LangChain4j 提供了一个用于自动配置的 Spring Boot 启动器，
支持 AI Services、检索增强生成（RAG）、工具调用等。

假设你已经导入了上述某个集成启动器，请接着导入
langchain4j-spring-boot4-starter（Spring Boot 4）或 langchain4j-spring-boot-starter（Spring Boot 3）：

Spring Boot 4：

```
<dependency> <groupId>dev.langchain4j</groupId> <artifactId>langchain4j-spring-boot4-starter</artifactId> <version>1.22.0-beta32</version></dependency>
```

Spring Boot 3：

```
<dependency> <groupId>dev.langchain4j</groupId> <artifactId>langchain4j-spring-boot-starter</artifactId> <version>1.22.0-beta32</version></dependency>
```

现在你可以定义 AI Service 接口，并使用 @AiService 对其进行注解：

```
@AiServiceinterface Assistant { @SystemMessage("You are a polite assistant") String chat(String userMessage);}
```

你可以将其视作一个标准的 Spring Boot @Service，但具备 AI 能力。

应用启动时，LangChain4j 启动器会扫描类路径，
找到所有使用 @AiService 注解的接口。
对于每一个发现的 AI Service，它会使用应用上下文中所有可用的 LangChain4j 组件
创建该接口的一个实现，并将其注册为 Bean，
以便你在需要的地方自动注入它：

```
@RestControllerclass AssistantController { @Autowired Assistant assistant; @GetMapping("/chat") public String chat(String message) { return assistant.chat(message); }}
```

### 自动组件装配

如果应用上下文中存在以下组件，它们将被自动装配到 AI Service 中：

- ChatModel
- StreamingChatModel
- ChatMemory
- ChatMemoryProvider
- ContentRetriever
- RetrievalAugmentor
- ToolProvider
- ToolExecutionErrorHandler 与 ToolArgumentsErrorHandler（参见错误处理）
- 任何 @Component 或 @Service 类中使用 @Tool 注解的所有方法

示例：

```
@Componentpublic class BookingTools { private final BookingService bookingService; public BookingTools(BookingService bookingService) { this.bookingService = bookingService; } @Tool public Booking getBookingDetails(String bookingNumber, String customerName, String customerSurname) { return bookingService.getBookingDetails(bookingNumber, customerName, customerSurname); } @Tool public void cancelBooking(String bookingNumber, String customerName, String customerSurname) { bookingService.cancelBooking(bookingNumber, customerName, customerSurname); }}
```

注意：如果应用上下文中存在多个同类型的组件，应用启动将会失败。
此时，请使用显式装配模式（详见下文）。

### 显式组件装配

如果你有多个 AI Service，并希望为每个 AI Service 装配不同的 LangChain4j 组件，
可以通过显式装配模式（@AiService(wiringMode = EXPLICIT)）指定要使用的组件。

假设我们配置了两个 ChatModel：

```
# OpenAIlangchain4j.open-ai.chat-model.api-key=${OPENAI_API_KEY}langchain4j.open-ai.chat-model.model-name=gpt-4o-mini# Ollamalangchain4j.ollama.chat-model.base-url=http://localhost:11434langchain4j.ollama.chat-model.model-name=llama3.1
```

```
@AiService(wiringMode = EXPLICIT, chatModel = "openAiChatModel")interface OpenAiAssistant { @SystemMessage("You are a polite assistant") String chat(String userMessage);}@AiService(wiringMode = EXPLICIT, chatModel = "ollamaChatModel")interface OllamaAssistant { @SystemMessage("You are a polite assistant") String chat(String userMessage);}
```

注意：在这种情况下，你必须显式指定所有组件。

#### 通过配置选择组件

除了硬编码 Bean 名称之外，你还可以使用属性占位符，
从而可以通过配置（例如根据不同的环境或 profile）改变装配到 AI Service 中的组件：

```
my-app.assistant.chat-model-bean=ollamaChatModelmy-app.assistant.tool-beans=weatherTools,calendarTools
```

```
@AiService( wiringMode = EXPLICIT, chatModel = "${my-app.assistant.chat-model-bean:openAiChatModel}", tools = "${my-app.assistant.tool-beans}")interface Assistant { String chat(String userMessage);}
```

需要注意以下几点：

- 占位符必须解析为一个 Bean 名称（例如 ollamaChatModel），而不是 LLM 模型的名称（例如 llama3.1）。
  模型名称在 ChatModel Bean 本身进行配置（例如 langchain4j.ollama.chat-model.model-name）。
- 可以在冒号后指定默认值：${my-app.assistant.chat-model-bean:openAiChatModel}。
- 如果占位符无法解析且没有默认值，则应用启动失败。
- 如果占位符解析为空值，则该属性将被视为未设置。
- 对于 tools，占位符可以解析为多个以逗号分隔的 Bean 名称。

更多详情可参见此处
（Spring Boot 4 版本使用相同的 API）。

### 监听 AI Service 注册事件

以声明式方式完成 AI Service 的开发后，你可以通过实现
ApplicationListener<AiServiceRegisteredEvent> 接口来监听 AiServiceRegisteredEvent 事件。
当 AI Service 在 Spring 上下文中注册时将触发该事件，
你可以在运行时获取所有已注册的 AI Service 及其工具的相关信息。
示例如下：

```
@Componentclass AiServiceRegisteredEventListener implements ApplicationListener<AiServiceRegisteredEvent> { @Override public void onApplicationEvent(AiServiceRegisteredEvent event) { Class<?> aiServiceClass = event.aiServiceClass(); List<ToolSpecification> toolSpecifications = event.toolSpecifications(); for (int i = 0; i < toolSpecifications.size(); i++) { System.out.printf("[%s]: [Tool-%s]: %s%n", aiServiceClass.getSimpleName(), i + 1, toolSpecifications.get(i)); } }}
```

## Flux

在流式响应场景下，你可以使用 Flux<String> 作为 AI Service 的返回类型：

```
@AiServiceinterface Assistant { @SystemMessage("You are a polite assistant") Flux<String> chat(String userMessage);}
```

为此，请导入 langchain4j-reactor 模块。
更多细节参见此处。

该模块还为非阻塞模式提供了 Mono<T> 与 Flux<AiServiceStreamingEvent>，
并且可以通过设置 langchain4j.executor.use-spring-task-executor=true，
让启动器将 LangChain4j 的异步工作路由到 Spring 自带的任务执行器，
从而使链路追踪、MDC 和安全上下文能够跟随异步调用传递。

OpenAI、Mistral AI 和 Ollama 启动器使用 Spring 的 HTTP 客户端发送请求：
阻塞调用使用 RestClient，非阻塞模式使用 WebClient。因此，当你使用上述启动器
以及支持非阻塞模式的提供商时（参见提供商支持），需要将 WebClient 放在类路径上。
Flux<String> 与 TokenStream 不需要 WebClient。

- Spring Boot 4：添加 spring-boot-starter-webclient。
- Spring Boot 3：添加 org.springframework:spring-webflux。如果你的应用不是 Web 应用（没有
  spring-boot-starter-web），还需要设置 spring.main.web-application-type=none，
  因为 Spring Boot 会将类路径上包含 spring-webflux 的应用视为响应式 Web 应用。
  除非你的应用是一个 WebFlux 应用，否则不要为此目的引入 spring-boot-starter-webflux：
  它还会引入一个 Web 服务器。在没有 WebClient 的情况下，非阻塞调用会抛出
  AsyncNotSupportedException，并提示需要添加哪些依赖。

非阻塞请求由应用的 WebClient.Builder 构建，正如阻塞请求由 RestClient.Builder 构建一样。
因此，在每个 Builder 上配置的过滤器、默认请求头与可观测性设置都会生效，
为你的内部服务添加凭证的过滤器同样会作用于对模型提供商的请求。
两个 Builder 是相互独立配置的：对其中一个的自定义不会影响另一个。
对于非阻塞请求，Spring Boot 配置使用（包含其连接器自定义器）的连接器
会与 LangChain4j 中配置的超时组合使用；Spring Boot 其他 HTTP 客户端设置
（例如 SSL bundles）不会被应用。如果应用中存在多个 WebClient.Builder Bean，
且其中没有标记为 @Primary 的 Bean，LangChain4j 将改用一个新的 WebClient.builder()。
如果想为 LangChain4j 提供专用的 Builder，可以声明一个 WebClientBuilderHolder Bean：

```
@BeanWebClientBuilderHolder langchain4jWebClientBuilder() { return WebClientBuilderHolder.of(WebClient.builder());}
```

## 可观测性

要为 ChatModel 或 StreamingChatModel Bean 启用可观测性，
需要声明一个或多个 ChatModelListener Bean：

```
@Configurationclass MyConfiguration { @Bean ChatModelListener chatModelListener() { return new ChatModelListener() { private static final Logger log = LoggerFactory.getLogger(ChatModelListener.class); @Override public void onRequest(ChatModelRequestContext requestContext) { log.info("onRequest(): {}", requestContext.chatRequest()); } @Override public void onResponse(ChatModelResponseContext responseContext) { log.info("onResponse(): {}", responseContext.chatResponse()); } @Override public void onError(ChatModelErrorContext errorContext) { log.info("onError(): {}", errorContext.error().getMessage()); } }; }}
```

应用上下文中每一个 ChatModelListener Bean 都将被自动注入到
由我们的 Spring Boot 启动器创建的所有 ChatModel 与 StreamingChatModel Bean 中。

### Micrometer 指标

将 langchain4j-micrometer-metrics 依赖添加到你的项目中：

Maven：

```
<dependency> <groupId>dev.langchain4j</groupId> <artifactId>langchain4j-micrometer-metrics</artifactId> <version>1.22.0-beta32</version></dependency>
```

Gradle：

```
implementation 'dev.langchain4j:langchain4j-micrometer-metrics:1.22.0-beta32'
```

#### Micrometer（Actuator）配置

你的项目还应包含必要的 Actuator 依赖。
例如，如果你正在使用 Spring Boot，可以将以下依赖添加到你的 pom.xml 中：

Maven：

```
<dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-actuator</artifactId></dependency>
```

Gradle：

```
implementation 'org.springframework.boot:spring-boot-starter-actuator'
```

在你的配置文件中启用 /metrics Actuator 端点。

application.properties：

```
management.endpoints.web.exposure.include=metrics
```

application.yaml：

```
management: endpoints: web: exposure: include: metrics
```

#### 配置 MicrometerMetricsChatModelListener Bean

在 Spring Boot 应用中，你可以将该监听器定义为 Bean 并注入 MeterRegistry：

```
import dev.langchain4j.micrometer.metrics.listeners.MicrometerMetricsChatModelListener;import io.micrometer.core.instrument.MeterRegistry;import org.springframework.context.annotation.Bean;import org.springframework.context.annotation.Configuration;@Configurationpublic class MetricsConfig { @Bean public MicrometerMetricsChatModelListener listener(MeterRegistry meterRegistry) { return new MicrometerMetricsChatModelListener(meterRegistry); }}
```

#### 查看指标

你可以通过访问应用的 /actuator/metrics 端点查看指标。

例如，如果你的应用运行在 localhost:8080，
可以访问 http://localhost:8080/actuator/metrics 查看指标。

##### Token 使用量指标

在以下地址查看 token 使用量指标：

```
http://localhost:8080/actuator/metrics/gen_ai.client.token.usage
```

##### 按 Token 类型过滤

gen_ai.token.type 标签用于指示这些 token 是用于输入还是输出：

| Token 类型 | 端点 |
| 输入 token | /actuator/metrics/gen_ai.client.token.usage?tag=gen_ai.token.type:input |
| 输出 token | /actuator/metrics/gen_ai.client.token.usage?tag=gen_ai.token.type:output |

注意：gen_ai.client.token.usage 指标是一个直方图（DistributionSummary）。
不带任何标签的端点显示跨所有 token 类型、模型与提供商的聚合统计（计数、总数、最大值）。

## 支持的版本

LangChain4j 的 Spring Boot 集成需要 Java 17，并同时支持：

- Spring Boot 4（4.0+）—— 使用以 -spring-boot4-starter 为后缀的启动器
- Spring Boot 3（3.5+）—— 使用以 -spring-boot-starter 为后缀的启动器，符合 Spring Boot OSS 支持策略

两个系列的启动器同步发布，并使用相同的版本号。请选择与你项目中 Spring Boot 版本相匹配的启动器套件。
